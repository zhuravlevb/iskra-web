# ROADMAP

Путь Iskra Web до MVP. Файл рабочий: закрыли пункт → поставили галочку здесь же, в том же
коммите. Обоснования решений — в `iskra-web.md`; здесь — что сделано, что нет и что дальше.

## Этап 0. Прототипы рисков

Каждый требует настоящего устройства или настоящего аккаунта, поэтому идёт руками, а не в CI.
Результат каждого пункта записывается сюда же, с датой и версиями браузеров.

- [ ] Кодеки: голосовое и квадратное видео из Chrome (Windows, Android), Firefox (Linux),
      Safari (macOS) играются в нативной Искре на iPhone
- [ ] Виртуализированная лента: подгрузка вверх без прыжков, картинки не меняют высоту,
      изменение ширины окна не сбивает место чтения
- [ ] Вход через MAS на matrix.org с динамической регистрацией клиента; как MAS относится
      к `http://localhost`
- [ ] Хранилище: `persist()` в Chrome-PWA, Chrome-вкладке, Firefox; Safari после недели без
      визита — во вкладке и в Dock
- [ ] Web Locks + `launch_handler`: две вкладки, два запуска из дока
- [ ] Время первой загрузки WASM на среднем Android

## Этап 2. Вход и сессия

- [x] Экран входа в два шага, как в нативной Искре: «Где ваш аккаунт?» → вход. Один путь
      внутрь: OAuth/SSO по умолчанию, пароль — за фразой «У меня только логин и пароль»;
      «Создать аккаунт» — где сервер умеет `prompt=create` (`features/signin/SignIn.svelte`)
- [x] Поиск сервера: домен через `.well-known`, `@user:server`, полный адрес, http — только
      localhost (`core/auth/server.ts`)
- [x] Пароль — `loginRequest`; проверено на демо-сервере в Vitest и Playwright
- [x] Legacy SSO — редирект и `m.login.token` на обратном пути (`core/auth/signIn.ts`)
- [x] OAuth 2.0 (MAS) — динамическая регистрация, PKCE, `response_mode=fragment`,
      `TokenRefresher`; ожидание возврата — в `sessionStorage`
- [ ] **Проверить OAuth на matrix.org** — код написан по API `matrix-js-sdk` 42, но живого
      MAS здесь нет; нужен домен (метаданные клиента требуют https) — см. этап 0
- [x] Адрес возврата стирается `replaceState` первой строкой (`src/boot.ts`), до роутера и SDK
- [x] Токены и ключ криптохранилища — под неизвлекаемым AES-GCM-ключом, свой у каждого
      аккаунта (`core/storage/vault.ts`); тест проверяет, что в базе нет токена открытым
- [x] Rust-крипто: `initRustCrypto({ storageKey, cryptoDatabasePrefix })` — база зашифрована
      ключом из хранилища; WASM грузится под боевой CSP (Playwright)
- [x] `persist()` по браузерам: Chromium — молча; Firefox — плашка с объяснением, потом запрос;
      Safari-вкладка — «Добавьте Iskra в Dock»
- [x] Экран «Хранилище» с результатом `persisted()` — в настройках, этап 8
- [x] Лок одной вкладки: Web Locks + `BroadcastChannel`, «Перейти туда» (фокус или мигающий
      заголовок) и «Открыть здесь» (та вкладка останавливает клиент, потом отпускает лок)
- [ ] Проверить `launch_handler: focus-existing` на установленном PWA — руками, этап 0
- [x] Сон и пробуждение: `visibilitychange` + `online` → `retryImmediately()`; полоса
      «Нет соединения» с «Повторить»
- [x] Выход: подтверждение, `logout()` (OAuth — `revokeToken`), удаление кэша синхронизации,
      криптохранилища и записи аккаунта; без сети — локально всё равно всё удаляется
- [x] Сервер отозвал сеанс (`SessionLoggedOut`) — локально всё удаляется, на экране входа
      «Вход больше не действует»
- [x] Демо-сервер — сервер входа: `demo.iskra.invalid` (в dev ещё и просто `demo`), своя база,
      стирается при каждом новом входе; отвечает на запросы Rust-крипто

## Этап 4. Лента

- [x] `TimelineMapper` — чистая функция `MatrixEvent` → `Message`: текст, эмоут, уведомление,

      (`ResizeObserver`); одна страница в полёте, ждущий не уходит ни с чем; неудача — не
      страница; поколение против ответов после сброса ленты; «Не удалось открыть чат»
- [x] Серии (один человек, < 5 минут, один день) и разделители дней — `core/timeline/layout.ts`
- [x] Прокрутка без прыжков — свой якорь на верхнем видимом сообщении
      (`design/scrollAnchor.svelte.ts`): подгрузка сверху, смена ширины окна, новое снизу;

- [x] Прочитано — когда чат на экране, окно в фокусе и человек внизу
- [x] Лента — `role="log"` без зачитывания истории; новые входящие объявляет отдельная

- [x] Ссылки в тексте — кусками, без `innerHTML`; `rel="noopener noreferrer"`
- [x] Демо: отправка с эхом через синхронизацию и `transaction_id`, участники, «Сбой отправки»

## Решения, принятые по ходу

- **Переводы — свой модуль, не Paraglide.** Требование «пропущенный ключ — ошибка сборки»
  выполняет сам TypeScript (`keyof` русского каталога); остальное ловит тест. Компилятор
  сообщений ради пятнадцати строк не нужен. Пересмотреть, если понадобится ICU `select`.
- **Регистрация SW — своя, не `virtual:pwa-register`.** Под Trusted Types адрес скрипта
  SW должен быть `TrustedScriptURL`; политика `iskra-sw` пропускает только `/sw.js`.
- **Иконка — `iskra-spark`**, иконка по умолчанию нативной Искры в ветке dev.
- **Тексты — «Iskra» латиницей**, как в Localizable.strings нативной Искры, и ключи оттуда же.
- **`signIn.readyHelp` — не дословно.** В нативной Искре «Мы откроем браузер…», но здесь
  человек уже в браузере: «Мы откроем страницу вашего сервера…».
- **Модули с рунами импортируются как `*.svelte.ts`**, с полным расширением: иначе правило
  «core/ не импортирует компоненты» не отличит `./app.svelte` от компонента.
- **Упоминание — не красный значок.** План говорил о трёх цветах непрочитанного (красный для
  упоминания), но нативная Искра в dev ушла от этого: красный в списке чатов читается как
  ошибка. Теперь как там: акцентное число, серое у беззвучного, «@» рядом при упоминании.
- **Список чатов — без TanStack Virtual.** Строки одной высоты, и `content-visibility: auto`
  даёт главное — вне экрана не раскладывать и не рисовать, — не ломая поиск по странице,
  фокус и скринридер. TanStack Virtual остаётся для ленты, где он действительно нужен.
- **Лента — без TanStack Virtual, со своим якорем.** Главное в плане — якорь на видимом
  элементе, и он сделан сам: реальные элементы в DOM меряются браузером, а не оценкой, и
  переносы строк при смене ширины окна учитываются бесплатно. Если на телефоне длинная
  переписка затормозит — виртуализация встанет поверх того же якоря.
- **Якорь — одна сверка, и никаких оценочных высот.** CI в трёх движках показал, что
  прокрутка и изменение раскладки приходят в разном порядке, а оценочная высота
  `content-visibility` у ещё не нарисованных строк сдвигает якорь на разницу с настоящей.
  Правило: сдвинулся `scrollTop` — это человек, запомнить; не сдвинулся — это раскладка,
  вернуть якорный элемент на место; перед своей переменой ленты — та же сверка
  (`capture()`). Индикатор подгрузки — плашкой поверх, не строкой в ленте.
- **Разделитель дня — не якорь.** Подгруженная история того же дня встаёт под него, и он
  остаётся на месте, пока всё под ним уезжает (найдено тестом на прыжок).
- **Демо-сервер не стерилен к крипто:** Rust-крипто поднимается и в демо, сервер отвечает на
  `keys/*` и честно говорит «бэкапа нет» (404 на `room_keys/version`).
- **Шаг восстановления — после *нового* входа, не после перезагрузки.** Перезагрузка
  страницы — не повод снова спрашивать; о запертой переписке напоминает плашка.
- **Ключ секретного хранилища — только на время операции.** Ни на диск, ни в IndexedDB:
  код существует затем, чтобы пережить потерю устройства, и копия на нём же бессмысленна
  (`core/encryption/secretStorageKey.ts`).
- **Демо отвечает на `keys/query` только о тех, о ком спросили.** Ответ ключами Алисы на
  вопрос об Ане подсовывал Rust-крипто старую личность посреди «Начать заново», и оно
  выбрасывало свежие закрытые ключи как не совпавшие. Найдено тестом.
- **Демо отвечает не раньше следующей макрозадачи.** На одних микрозадачах цикл исходящих
  запросов Rust-крипто не отдавал очередь таймерам, и запись данных аккаунта зависала.
- **Меню — нативный `<dialog>`.** Верхний слой не обрезается трансформациями колонок,
  фокус и `Esc` — даром. Закрываясь, он возвращает фокус туда, откуда открыт, поэтому
  всё, что после пункта меню ставит фокус само (ответ, правка), делает это кадром позже.
- **Долгое нажатие — свой таймер, а не только `contextmenu`.** Android присылает
  `contextmenu` на долгое касание сам, iOS — нет, а панели по наведению у пальца нет:
  без таймера на iPad меню не открылось бы никак. `contextmenu` сразу после таймера
  гасится, чтобы меню не открылось дважды.
- **`formatted_body` — фрагментом, не строкой.** DOMPurify разбирает HTML через свою
  политику Trusted Types, результат вставляется `replaceChildren`; ни одна наша строчка
  не пишет в `innerHTML`. Цвета и стили отбрасываются: CSP их не пустит, а контраст — наш.
- **Черновик — не на сервере.** Matrix не хранит черновики, а в данных аккаунта они
  ушли бы на все устройства открытым текстом. Локально, под ключом аккаунта.
- **`uploadContent` в демо — мимо.** В браузере SDK грузит файлы через `XMLHttpRequest`
  (ради прогресса), а не через `fetchFn` клиента, и демо-сервер, живущий в `fetchFn`,
  загрузку бы не увидел. Для демо загрузка идёт своим `fetch`; путь шифрования — тот же.
- **Библиотека шифрования вложений — `matrix-encrypt-attachment`** (Apache-2.0, 9 КБ,
  только WebCrypto), как в плане: хэш при расшифровке она проверяет сама и без хэша не
  расшифровывает. Своя реализация AES-CTR ничего бы не добавила, кроме риска.
- **SVG — не `m.image`.** Уходит файлом: многие клиенты его не покажут. Показываем чужой
  SVG только в `<img>` (там он не исполняет скриптов) и по `blob:`-адресу никуда не переходим.
- **Приглашение просит ключи комнаты.** Rust-крипто, приглашая, достаёт из бэкапа ключи этой
  комнаты — чтобы передать приглашённому историю — и неизвестный маршрут в демо ронял всё
  приглашение. Юнит-тест без крипто этого не видел; нашёл e2e.
- **Настройки — одна страница с разделами, а не дерево экранов.** На десктопе разделы
  видны сразу, адрес ведёт к разделу (`#/settings/storage`); на телефоне — та же страница
  вместо списка, как чат.
